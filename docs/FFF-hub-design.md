# FFF 포트폴리오 허브 설계안 (구상 단계)

> 목표: **회전 네비게이션 → 포스터 클릭 → 독립 프로젝트 진입** 구조를 현재 기술로 직접 설계·구현한 허브.
> 원칙: 구조만 차용, 비주얼/에셋/코드는 전부 자체 제작 (원본 사이트는 레퍼런스로 한 번 보고 닫기).

---

## 1. 한 줄 컨셉
"하나의 허브, 여러 개의 독립된 세계." 허브는 가볍고 아름답게, 각 프로젝트는 서로 영향을 주지 않게.

## 2. 핵심 설계 결정 (내가 고른 방향)

| 항목 | 선택 | 이유 |
|---|---|---|
| 프레임워크 | **Next.js (App Router) + TypeScript** | 라우팅, 코드 스플리팅, 배포(Vercel)가 한 번에 해결 |
| 허브 3D | **Three.js (+ React Three Fiber)** | 선언적으로 포스터 배치·상태 관리가 쉬움 |
| 렌더러 | **WebGPURenderer 우선, WebGL 자동 폴백** | 최신 흐름이면서 미지원 브라우저도 커버 (착수 시점에 R3F 쪽 지원 상태 재확인) |
| 모션 | **GSAP** (+ 필요 시 Lenis) | 관성, 스냅, 전환 시퀀스 제어 |
| 페이지 전환 | **View Transitions API + GSAP Flip** | 포스터가 확대되며 프로젝트로 이어지는 연출 |
| 프로젝트 격리 | **마운트 계약(동적 import) 기본, 레거시는 iframe sandbox** | 아래 5장 참고 |
| 저장소 | 기존 `ai-playground` 모노레포 안에 `apps/hub` + `projects/*` | 프로젝트별 독립 개발 후 등록만 |

## 3. 폴더 구조 (안)

```
ai-playground/
├─ apps/
│  └─ hub/                      # Next.js 허브
│     ├─ app/
│     │  ├─ page.tsx            # 회전 네비 (메인)
│     │  └─ p/[slug]/page.tsx   # 프로젝트 진입 페이지
│     ├─ components/hub/        # Ring, Poster, Cursor, Loader ...
│     └─ lib/registry.ts        # 프로젝트 목록 로딩
├─ projects/
│  ├─ www/                      # 현재 진행 중인 프로젝트
│  ├─ landmark-planet/
│  └─ <game-or-experiment>/     # 각자 독립 패키지
├─ packages/
│  ├─ project-contract/         # mount/unmount 타입 정의
│  └─ ui-tokens/                # 공통 색/타이포 (최소한만)
└─ docs/
```

## 4. 허브 화면 설계

### 4-1. 회전 네비게이션
- 포스터를 3D 원통/링 위에 배치, **드래그 + 휠 + 터치**로 회전
- **관성(inertia) + 가장 가까운 포스터로 스냅**
- 중앙 포스터만 선명, 나머지는 살짝 어둡고 블러 (깊이감)
- 호버/포커스 시 포스터 셰이더 반응 (미세한 왜곡, 색수차, 빛 번짐) — 과하지 않게, 한 가지 시그니처 효과만
- 배경: 아주 느린 파티클 또는 그라디언트 노이즈로 "살아있는" 느낌

### 4-2. 포스터
- 프로젝트마다 **1장의 포스터 이미지(또는 짧은 루프 영상 텍스처)** + 제목/연도/태그
- 텍스처는 **KTX2/WebP로 압축**, 해상도 2단계(썸네일 → 선택 시 고해상도)
- 포스터 비주얼은 이미지 생성(AI) + 직접 편집으로 제작 가능 (저작권 안전한 자체 에셋)

### 4-3. 진입 전환 (포스터 → 프로젝트)
1. 클릭한 포스터가 화면 중앙으로 이동하며 확대 (허브 씬 안에서)
2. 동시에 프로젝트 코드 **프리로드 시작** (이미 hover에서 시작해뒀다면 즉시)
3. 포스터가 화면을 채우는 순간 프로젝트 마운트, 크로스페이드
4. 뒤로가기 시 역재생 (포스터가 원래 자리로 복귀)

## 5. 프로젝트 격리 방식 (가장 중요한 부분)

### 5-1. 마운트 계약 (내가 만든 프로젝트용)
각 프로젝트는 아래 하나만 지키면 허브에 꽂을 수 있어요.

```ts
// packages/project-contract
export interface ProjectModule {
  mount(container: HTMLElement, ctx: { signal: AbortSignal }): Promise<void> | void;
  unmount(): void; // 렌더 루프 정지, 이벤트 해제, WebGL dispose
}
```

- 허브는 `import('projects/xxx')`로 **클릭 시점에만** 코드를 가져옴
- 프로젝트는 자기 렌더러/루프를 만들고, 나갈 때 `unmount()`에서 전부 정리

### 5-2. iframe sandbox (오래된 코드, 다른 버전 라이브러리, 외부 프로젝트)
- 10년 전 순수 JS 캔버스 게임처럼 **리팩토링 전 코드**는 일단 iframe으로 감싸서 먼저 입주
- `sandbox` 속성으로 권한 최소화, 나중에 시간 날 때 계약 방식으로 이주

### 5-3. 선택 기준
| 상황 | 방식 |
|---|---|
| 새로 만드는 프로젝트 | 마운트 계약 |
| 레거시 / 버전 충돌 가능 | iframe |
| 풀스크린 게임, 자체 WebGL 컨텍스트 | 둘 중 아무거나, 단 **허브 렌더러는 일시정지** |

## 6. 성능 설계 (용량·프레임 걱정 해소)

- **초기 번들은 허브만**: 회전 네비 + 포스터 썸네일. 프로젝트 코드는 0
- **WebGL/WebGPU 컨텍스트는 동시에 1개 원칙**: 프로젝트 진입 시 허브 렌더 루프 정지(또는 컨텍스트 해제), 복귀 시 재개
- hover/idle 시점에 **다음 후보 프로젝트 프리페치** (모바일 데이터 환경에서는 비활성)
- `devicePixelRatio` 상한(예: 2), 저사양 감지 시 셰이더 효과 자동 단순화
- 프로젝트별 **성능 예산** 문서화 (초기 JS 크기, 에셋 총량, 목표 FPS)
- 에셋은 CDN + 긴 캐시, 서비스워커는 2차 단계에서

## 7. 접근성 · 모바일 · SEO (놓치기 쉬운 것들)
- `prefers-reduced-motion` 시 회전/전환 연출 최소화
- **키보드 내비게이션**(좌우 화살표로 회전, Enter로 진입) + 스크린리더용 목록
- 모바일/WebGL 불가 환경용 **단순 그리드 폴백**
- 프로젝트마다 `/p/[slug]` 정적 메타데이터(OG 이미지) → 링크 공유 시 예쁘게 보임

## 8. 보안 (배포 단계)
- Vercel 배포 + `next.config`에 **CSP, HSTS, frame-ancestors** 등 보안 헤더
- iframe 프로젝트는 `sandbox` 최소 권한
- Dependabot + CI에서 audit, secret scanning
- 백엔드(Supabase 등) 붙이면 RLS 필수

## 9. 단계별 로드맵

| 단계 | 내용 | 완료 기준 |
|---|---|---|
| **M0 스파이크** | 예전에 하다 멈춘 폴리곤 실험 재검토, 링 회전 + 스냅 프로토타입 | 더미 포스터 8장이 부드럽게 회전·스냅 |
| **M1 허브 뼈대** | Next.js 허브, registry, 포스터 컴포넌트, 키보드/터치 입력 | 데스크톱·모바일에서 조작 가능 |
| **M2 전환** | 포스터 → 프로젝트 확대 전환, 뒤로가기 역재생 | 끊김 없이 왕복 |
| **M3 계약 + 첫 입주** | project-contract, `www` 및 1~2개 프로젝트 입주, 허브 렌더 일시정지 로직 | 프로젝트 3번 왕복해도 메모리 증가 없음 |
| **M4 폴리시** | 시그니처 셰이더, 사운드(선택), 로딩 연출, 접근성/폴백 | 저사양 기기에서도 쾌적 |
| **M5 배포** | 보안 헤더, OG 이미지, 도메인, 성능 측정 | Lighthouse·실기기 점검 통과 |

## 10. 작업 방식 제안
- **Claude Code(Code 탭)에서 모노레포 열고 진행**, 마일스톤마다 브랜치 분리
- 루트에 `CLAUDE.md`로 규칙 고정: 마운트 계약, 성능 예산, 폴더 규칙, "원본 사이트 디테일 복제 금지"
- 검증 루틴: 프로젝트 왕복 10회 후 메모리/컨텍스트 개수 확인하는 체크 스크립트

## 11. 착수 전에 정하면 좋은 것 (열린 결정)
1. **허브 형태**: 정통 원형 링 vs 나선/구형 등 변형 (자체 아이덴티티를 위해 한 가지 변주를 추천)
2. **R3F vs 순수 Three.js**: Three.js 학습이 목적이면 순수 Three.js, 속도가 목적이면 R3F
3. **WebGPU를 필수로 할지, 폴백만 둘지**
4. **초기 입주 프로젝트 개수**: 3개 정도로 시작 추천 (계약 검증에 충분)
5. **사운드 유무**
6. **포스터 제작 방식**: AI 생성 + 직접 보정 / 직접 일러스트 / 3D 렌더 캡처
