# Rubber Duck Pool 진행 계획서

지휘하는 모델이 바뀌어도 같은 방식으로 일을 이어가기 위한 문서입니다. 지휘자는 이 문서와 `CLAUDE.md`, `docs/worklog.md`의 마지막 몇 묶음, `improvements.md`의 마지막 절을 읽고 시작합니다.

## 1. 역할

| 누구 | 맡는 일 | 부르는 법 |
|---|---|---|
| 지휘자 (Fable, 없으면 그 자리의 모델) | 무엇을 할지 정하고, 브리프를 쓰고, 결과를 확인해 들이고, 사용자에게 보고합니다. 코드는 한두 줄짜리 수정만 직접 씁니다. | 이 세션 |
| Opus | 여러 파일에 걸친 설계와 구현(큰 코딩) | Agent 도구, `model: opus`. 체크아웃은 지휘자가 미리 만들어 경로를 줍니다. |
| Gemini Carbon | Opus와 같은 큰 코딩 | 지금은 `agy models`에 없습니다. 생기면 Opus와 나눕니다. |
| Gemini Argon | 범위가 좁은 구현(작은 코딩) | `agy -p … --model gemini-4-argon-medium`. 한도가 소진되면(429) Hydrogen이 대신합니다. |
| Gemini Hydrogen | 리팩터링, 디버깅, 최적화, 테스트 보강으로 Argon을 돕습니다. | `agy -p … --model gemini-4-hydrogen-high` |
| GPT-6.1 Terra Max | 다른 모델이 요청한 에셋을 만듭니다. 참고 모델은 `resort-cooler-reference-v4-open`과 `deck-chair-atelier`입니다. Blender 실행은 지휘자가 합니다. | `codex exec -m gpt-6.1-terra …` (max) |
| GPT-6.1 Sol xHigh | 리뷰만 합니다. 파일을 고치지 않습니다. | `codex exec -m gpt-6.1-sol -c model_reasoning_effort='"xhigh"' -s read-only …` |

에셋은 `models/`와 production에 있는 완성본을 먼저 쓰고, 필요하다고 판단될 때만 새로 만듭니다.

## 2. 한 바퀴

일은 아래 순서를 되풀이합니다. 한 바퀴는 커밋 하나로 끝납니다.

1. **찾기.** 할 일은 세 곳에서 나옵니다: Sol 리뷰의 발견, `improvements.md`의 `[남김]`, 사용자의 말. 할 일이 떨어지면 Sol에게 아직 리뷰하지 않은 영역을 맡깁니다(4절의 목록).
2. **확인.** 발견을 그대로 믿지 않습니다. 지휘자가 지목된 코드를 읽고, 플레이어가 실제로 겪는 일인지 판단합니다. 겪지 않는 일이면 `improvements.md`에 `[안 함]`과 이유를 적고 끝냅니다.
3. **나누기.** 한 단위는 원인 하나입니다. 같은 파일을 건드리는 단위는 동시에 내보내지 않습니다. 크기로 맡을 모델을 고릅니다: 한두 줄은 지휘자, 한 파일 안의 수정과 테스트는 Argon(없으면 Hydrogen), 새 구조나 여러 파일은 Opus.
4. **브리프.** 받는 쪽은 이 대화를 모릅니다. 브리프에 다음을 다 적습니다.
   - 무엇이 잘못됐고 플레이어가 무엇을 보는지, 원인이 있는 파일과 줄
   - 무엇을 바꾸고 무엇은 그대로 두는지
   - 테스트: 고치기 전 코드에서 실패해야 한다는 것과, 그것을 한 번 돌려 확인하라는 것
   - 문서: `docs/worklog.md` 끝에 다음 번호의 묶음, `improvements.md` 끝에 `[고침]` 한 줄
   - 커밋 메시지 형식과 크레딧 줄, 푸시 금지, 자기 체크아웃 밖을 건드리지 말 것
   - 마지막에 보고할 것: 커밋 해시, 바꾼 파일, 테스트 수 전후, 스스로 내린 판단
5. **체크아웃.** 에이전트마다 따로 둡니다(`$TMPDIR/agy-h`, `$TMPDIR/agy-a` 등). 시작 전에 지휘자가 현재 브랜치 머리로 옮기고, 깨끗한지 봅니다. Agent 도구의 워크트리 격리는 origin/main에서 시작하므로 쓰지 않습니다.
6. **들이기.** 에이전트의 보고가 아니라 diff를 읽습니다. 이상이 없으면 cherry-pick하고, `worklog.md` 충돌은 양쪽을 다 살리고 번호를 다시 매깁니다.
7. **증명.** 아래 셋을 다 통과해야 푸시합니다.
   - `npm run verify`의 종료 코드 0 (`&&`와 `tail`로 가리지 않습니다)
   - 브라우저 드라이브 19개(`.claude/skills/verify/drive/pool-*.js`)
   - 화면에 보이는 변화라면 전후 스크린샷과, 잴 수 있으면 숫자
8. **리뷰.** 들인 커밋을 Sol에게 보냅니다. 발견이 나오면 1로 돌아갑니다. 테스트가 약하다는 지적(고장 난 코드에서도 통과)은 수정과 같은 무게로 다룹니다.
9. **기록.** PR 본문을 고치고, 사용자에게 한국어로 짧게 알립니다.

## 3. 판단 기준

- **플레이어가 먼저입니다.** 고칠지 말지는 플레이어가 보거나 겪는지로 정합니다. 코드가 깔끔해지는 것만으로는 단위를 만들지 않습니다.
- **원인을 고칩니다.** 증상이 난 곳이 아니라 처음 틀어진 곳을 고칩니다. 같은 함수를 부르는 다른 곳도 같은 문제를 겪는지 먼저 봅니다.
- **가장 작은 변경.** 새 옵션, 새 추상화, 나중을 위한 뼈대는 넣지 않습니다. 공용 패키지(`packages/`)를 바꾸면 주지 않았을 때 전과 똑같이 동작하게 합니다(jelly의 수조 넷이 함께 씁니다).
- **테스트는 고장을 잡아야 합니다.** 새 테스트는 고치기 전 코드에서 실패하는 것을 눈으로 확인합니다. 구현이 아니라 플레이어나 호출자가 보는 결과를 단언합니다.
- **숫자에는 근거를.** 성능이나 밝기 같은 숫자는 무엇을 어떻게 쟀는지와 함께 적습니다. 기계가 바쁠 때 넘친 시간 검사는 혼자 다시 돌려 둘 다 적습니다.
- **모르면 모른다고.** 확인하지 못한 것은 통과했다고 쓰지 않습니다. 에이전트가 권한 때문에 막혔다고 하면 지휘자가 대신 돌려 주지 않고, 다른 길을 찾거나 사용자에게 알립니다.
- **묻지 않고 진행하는 것:** 되돌릴 수 있는 모든 일. **사용자의 허락이 필요한 것:** 파일 삭제, 다운로드, 범위 밖 기능, 보류 중인 것의 재개.

## 4. 범위

- **하는 것:** 한 번의 방문(풀, 오리, 앉기, 도감, 보트, 집에 가기)이 끊기지 않고 자연스러운 것. 고침, 보완, 리팩터링, 성능.
- **하지 않는 것:** 실패 상태, 타이머, 점수, 재화, 멀티플레이, 새 지역, 레이스, 꾸미기 메뉴. 합성음은 끈 채로 둡니다.
- **보류:** 시각 디자인(UI의 색, 글꼴, 모양)과 폰 레이아웃.
- **그대로 두는 것:** web-ocean에서 온 바다와 해안, 사용자의 쿨러 모델, 의자.
- **베끼지 않습니다.** 참고한 것에서는 구조와 생각만 가져옵니다.

아직 Sol이 리뷰하지 않은 영역(할 일이 떨어지면 여기서 고릅니다):
- 소리와 라디오(`sound.js`, `radio.js`): 겹침, 끊김, 탭 가림 뒤 복귀
- 앉기와 카메라(`seating.js`, `navigation.js`): 앉은 채 할 수 있는 일, 일어서는 조건
- 도감 화면(`book-view.js`): 키보드와 화면 읽기, 긴 목록
- 하루의 시간(`daylight.js`, 밤의 불꽃과 반딧불): 경계 시각, 동작 줄이기
- 수집품과 보트(`collectibles`, 소환, 갈매기): 드문 순서

## 6. 커밋과 금지 목록

- 경로를 하나씩 적어 스테이징합니다. `git add -A`, `.`, `-u`와 메인 트리의 `git stash`는 쓰지 않습니다.
- 메시지 끝에는 일한 에이전트의 크레딧 줄을 적고, 마지막 줄은 지휘자의 것입니다.
- 절대 넣지 않는 것: `projects/rubber-duck-pool/docs/mcp-for-blender.md`, API 키와 OAuth 자격 증명, `.mcp.json`, `.claude/settings.json`, `*.blend1`, 사용자의 추적 안 된 스터디 파일들.
- `.claude/launch.json`은 고치지 않습니다. Codex 크레딧은 사지 않습니다.
- 페이지의 글은 영어, 사용자에게 하는 보고와 문서는 한국어입니다.
